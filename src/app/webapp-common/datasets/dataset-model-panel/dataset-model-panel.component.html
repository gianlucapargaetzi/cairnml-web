How datasets work

  • A dataset is a Git repository. Git holds the metadata: dataset.yaml, the footprint dataset.lock.json and the verify check. Each commit is one version of the data.
  • The data lives in Git LFS or in DVC storage. The storage is chosen when the dataset is created. With LFS the files are in the GitHub LFS of the repository; with S3 (the default) DVC keeps them in the dataset storage behind the CairnML server.
  • The registry records the pin. cairnml dataset register adds the repository to the dataset registry at its default branch. Public readers use the registry entry by name.
  • A run records the version it used. The run keeps the repository, the commit and the content hash, so the runs listed below use exactly the version shown.
  • Fetching a version by hand. With LFS: git clone, git checkout the commit, git lfs pull. With S3: cairnml dataset get with the repository and the commit. The commands for each version are below.
